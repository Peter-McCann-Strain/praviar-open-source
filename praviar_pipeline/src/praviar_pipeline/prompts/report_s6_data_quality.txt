This is ONE SECTION of a multi-section report. Sections 1-5 contain the substantive analysis. Your job is TRANSPARENCY — documenting exactly what data was available, what was not, and how that affects confidence in the conclusions. An attorney reviewing this report must understand the data foundation.

2. DATA LIMITATIONS — CRITICAL FOR DEFENSIBILITY
   - CLAIMS TEXT AVAILABILITY: How many patents had full claim text vs title/abstract only? This is the single most important data quality metric. State clearly: "X of Y analyzed patents (Z%) had claims text available. Remaining patents assessed via title/abstract inference only."
   - ANALYSIS FAILURES: Patents that failed analysis and why (timeout, data error, API failure)
   - DRAWING/STRUCTURE ANALYSIS: How many patents had OCSR (chemical structure drawing) analysis
   - PROSECUTION HISTORY: Availability of file wrapper data
   - PTAB DATA: Availability of PTAB proceedings
   - ORANGE BOOK / PURPLE BOOK: Whether regulatory listing data was available

3. CONFIDENCE CALIBRATION
   - If ALL primary sources succeeded and claims text was available: "HIGH confidence — analysis based on complete data."
   - If primary sources succeeded but claims text is unavailable for any material patent: "LOW confidence for clearance — title/abstract screening cannot support element-level infringement or a CLEAR determination. Retrieve authoritative claim text and repeat claim mapping."
   - If primary sources FAILED: "LOW confidence — [specific source] failure affects completeness of [specific aspect]. Updated search recommended."
   - State the overall confidence level for the report.

4. CRITIC / QA FINDINGS
   Report the portfolio-level quality assessment:
   - Quality score (from `get_critic_findings`)
   - Cross-patent consistency issues flagged
   - Risk-claim mismatches: for each mismatch, cite the patent ID, canonical label,
     exact claim/evidence contradiction, provenance, and release consequence. Preserve
     the canonical label as an attributed upstream value, but do not endorse or repeat
     it as reliable when the underlying evidence contradicts it. Mark the conclusion
     unresolved and require correction or counsel review.
   - Any patents flagged for optional manual verification

   ⚠ PROVENANCE AND CONFLICT RULE — CRITICAL: UPSTREAM CLAIM-COVERAGE SCREENS are attributed
   pipeline outputs, not authority that overrides claim evidence, status, verification,
   or QA. If a canonical level conflicts with material evidence, report both, do not
   silently substitute a new level, mark the decision UNCLEAR/BLOCKED, and require the
   upstream analysis to be corrected before release.

5. DATA FRESHNESS
   - Analysis date (from `get_current_date` or stated in data)
   - Data freshness warnings: if key sources are >12 months old, state explicitly: "CAUTION: Primary source data is [X] months old. Patent grants, litigation outcomes, and regulatory actions occurring since [date] are not reflected. Updated search recommended before commercial decisions."
   - Note that patent landscape is dynamic: 18-month publication lag for applications means recently filed applications are invisible.

6. KNOWN ARTIFACTS
   - Database-specific artifacts (e.g., BigQuery sometimes shows generic "2046-04-06" expiry dates that are artifacts, not actual patent terms)
   - Expiry date estimation limitations (20-year term from filing is an estimate; actual term requires PTA/PTE/terminal disclaimer verification)
   - Assignee data quality (some databases show original assignee, not current owner after assignments)
